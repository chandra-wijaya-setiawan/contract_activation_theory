# v1.5 — Delete LIFE, realign to admission-gate theory (DONE 2026-05-27)

## Why

Of 5 load-bearing CAT mechanisms in DESIGN.md, 4 were LIFE imports
(Action Realizer, Environment Spec preconditions, Circuit Breaker
F2/F3/F4, Failure Attribution taxonomy). The layer the theory is *named*
after (activation) was rhetorical — Step 6 was structurally identical to
ReAct's act phase. Before any new benchmark work, theory and code had to
match.

## What shipped

- Stripped all 4 LIFE imports from `cat/`
- Renamed Step 6 ACTIVATE → INVOKE
- Step 4 ACTIVATE is now the one-shot admission gate
  (boundary/environment/capacity → capability grant)
- Contract lifecycle as state machine:
  `LATENT → ELIGIBLE → ACTIVE → SUSPENDED → FULFILLED / FAILED / EXPIRED`
- 60+ unit tests passing on the stripped code

## Gate criteria all passed

- No LIFE refs in `cat/` (`git grep -i "life|action_realization|environment_contract|circuit breaker|free_form|criterion_fail_streak"` returns nothing relevant)
- Unit tests green
- One v14-PASS task still PASSes; one v14-FAIL task still FAILs (no regression)
- Every mechanism in DESIGN.md derivable from the contract axiom

## Decision log

- **LIFE Circuit Breaker (F2 replan)** replaced by SUSPENDED-with-watcher
  event-driven re-admission. Reason: F2 was a fall-through state-machine
  hack; the contract lifecycle already has SUSPENDED for this.
- **Failure Attribution taxonomy** replaced by contract-state reasons
  (which Criterion / Representation / admission check failed). Reason:
  substring matching on tool output is the wrong abstraction; the
  contract already knows what failed.
- **Action Realizer** removed; tool errors surface naturally. Reason:
  pre-normalizing LLM args hid real model errors; the next-turn tool
  error is sufficient signal.
- **Tool preconditions** (Environment Spec) removed; tools just run and
  report errors. Reason: preconditions duplicated tool error handling.
