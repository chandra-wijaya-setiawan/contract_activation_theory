# v1.7.2 — Framework-comparison hardening (FUTURE, gate before v2.0)

## Goal

Prove CAT matches or beats established agent FRAMEWORKS (not just frontier
models). **Gate to v2.0** — must pass before expanding to v2.0
prestige benchmarks (WebArena, OSWorld, Spider 2.0).

## Scope change vs prior plan

v1.7.1 SkillsBench (see PRD) already provides head-to-head against the
established **scaffolds** (Claude Code, OpenHands, Gemini CLI, Codex)
and **frontier models** (GPT-5.x, Opus, Sonnet, Gemini). What v1.8
adds is the comparison the leaderboard doesn't cover: **agent-framework
peers** (Pi, Hermes) and **consistency analysis** (pass^k).

## Engineering work

### 1. Head-to-head vs framework peers

Run Pi (Earendil) and Hermes (Nous) on the same swe10 + SkillsBench
slices we used for CAT. These are the frameworks most architecturally
adjacent to CAT — Pi is the minimalist primitives camp, Hermes is the
procedural-memory camp. The comparison is structural, not just about
scores.

Target: ≥ parity on solve rate + measurable advantage on either token
cost OR tool-call efficiency (CAT's known strengths).

### 2. AgentBench subset (THUDM, ICLR 2024)

- **OS environment** (Linux shell tasks, 144 instances)
- **DBBench** (SQL tasks, 261 instances)
- Optional: **ALFWorld** (household tasks, 134 instances)

All deterministic, published numbers available. Tests CAT on domain
shapes SkillsBench may not cover (specifically, low-iteration shell
tasks where the discipline overhead is highest).

### 3. Pass^k consistency

- pass^1, pass^2, pass^4 for SWE-bench, SkillsBench, AgentBench
- Consistency is the key differentiator for CAT — high pass^1 with low
  pass^4 means the agent is unreliable; CAT's claim is that contract
  discipline narrows this gap

## Gate criteria

- ≥ parity on solve rate vs Pi AND Hermes on the same benchmark slice
- Measurably cheaper OR fewer tool calls vs both (CAT's known
  strengths from v1.6.6.7-14)
- Pass^4 > 50% on solved instances
- Results published (internal report or external paper)

## If gate fails

Iterate on v1.7 (improve A.2 ELECTION quality, add SUSPENDED-resume B,
ship A* heuristic C) until criteria met. Do NOT proceed to v2.0.
