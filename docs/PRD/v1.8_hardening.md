# v1.8 — Coding domain hardening (FUTURE, gate before v2.0)

## Goal

Prove CAT matches or beats an established coding agent on a recognized
benchmark. **Gate to v2.0** — must pass before expanding to other domains.

## Engineering work

### 1. Head-to-head vs established agent

- Pick one of: Pi (Earendil), Hermes (Nous), Claude Code (Anthropic)
- Run on SWE-bench Lite (already integrated)
- Target: ≥ parity on solve rate + measurable advantage on token cost

### 2. AgentBench subset (THUDM, ICLR 2024)

- OS environment (Linux shell tasks, 144 instances)
- DBBench (SQL tasks, 261 instances)
- Optional: ALFWorld (household tasks, 134 instances)
- All deterministic, comparable to published numbers
- Criterion adapters: file/exit-code for OS, query-result for DB

### 3. Pass^k across environments

- pass^1, pass^2, pass^4 for SWE-bench, tau-bench, AgentBench
- Consistency is the key differentiator for CAT

## Gate criteria

- ≥ parity on solve rate vs at least one established agent
- Measurably cheaper (tokens or USD) on same benchmark
- Pass^4 > 50% on solved instances
- Results published (internal report or external paper)

## If gate fails

Iterate on v1.7 (improve failure handling, add skills, tune SUSPENDED
re-admission, derive real capability grants) until criteria met. Do NOT
proceed to v2.0.
